# Decision log

Last updated: 2026-10-27.

Each decision has a status:

- **Confirmed**: explicitly requested or approved by Fabio.
- **Proposed**: written by Claude, awaiting review. It holds until it is
  challenged, but it has not been discussed.
- **Open**: to be decided.

To change a decision the row is not deleted: a new one is added that
replaces it, and the old one is marked as superseded.

| D32 | An addon that cannot be downloaded (for example `allowModDistribution = false`) is installed by dragging into the window the zip downloaded by hand from the site, or by choosing it with "Install from zip…": the backend extracts it with the rules of D26, accepts only top-level folders with a `.toc` of the same name and replaces folders with the same name without confirmation. Afterwards, the addon is recognised by its fingerprint if it is on CurseForge, or by the free sources' markers (`## X-WoWI-ID`, Tukui folders); an addon that is only on GitHub stays without a source until it is added from the link, because GitHub is matched only from records | Completes D13 without circumventing it: the user does the download from the author's site. Approved in the "Free sources" specification (issues #102, #103) | Confirmed |
| D33 | Matching order of installed folders across sources: first the app's record in `installed-addons.json` (v2, per source and textual id), then the CurseForge fingerprint, then the free sources (`## X-WoWI-ID` in the `.toc`, `directories` folders for Tukui; GitHub only from records). A folder matched by one source is not reread by the others | Avoids duplicates when the same addon is on several sources; the source the app installed it from wins. Approved in the "Free sources" specification (issues #104, #105) | Confirmed |
| D34 | A CurseForge project that cannot be downloaded (`allowModDistribution` other than `true`) can fall back to GitHub releases (issue #162): the repository is derived **only** from the project's `sourceUrl` when it points to `github.com/<owner>/<repo>`, never by searching by name; the release is read with the existing GitHub source (cache, request limit, zip choice from `release.json`) and is valid only if it is **the same version** as the file the app would choose on CurseForge (`pick_file`): the same zip name, case-insensitively, or the tag without a leading `v` present as a whole version in the `fileName` or in the `displayName`. Projects that CurseForge serves never query GitHub | Avoids the manual download of the most popular blocked addons (Bartender4, Deadly Boss Mods) without installing a version different from the one published on CurseForge and without spending GitHub's limit of 60 requests an hour. Same-version rule chosen by the user | Confirmed |
| D37 | GitHub releases are read **without the API** (issue #179), only from `github.com`: the tag from the `Location` header of `github.com/{owner}/{repo}/releases/latest`, read without following the redirect (404 = no release, without calling the API), then the packager's `release.json` and the zip from `releases/download/{tag}/…`. The `Location` must be `https://github.com/{owner}/{repo}/releases/tag/{tag}` of the same repository (case-insensitively); a moved repository, which redirects to `releases/latest` under another name, is followed only once; a tag with `/` (valid for git) is read from the API; anything else is an error. The API (`GET /repos/{owner}/{repo}/releases/latest`, without a token) remains only as a fallback for a release **without `release.json`** (404 on that file), to choose the zip from the assets as before, and must give the same tag; the block after the limit of 60 requests an hour and its message apply only to this fallback. Without the API the release's publication date is not known. With reads outside the limit, import (`import_addons`) also uses the mirror of D34 for blocked CurseForge projects | The limit of 60 requests an hour stopped checks, updates and the mirror with only a few GitHub projects; tokens and OAuth are excluded by the user's choice. `releases/download/{tag}/` ties the zip and `release.json` to the same tag (verified on 2026-10-26 on BigWigs, Bartender4 and Auctionator). Completes D31 and D34 | Confirmed |

| D44 | The CurseForge third-party key (granted 2026-10-29) is never in the app, the repository, a build, CI or a release: it lives only in the secrets of the Cloudflare Worker [`FabioSM46/wow-don-proxy`](https://github.com/FabioSM46/wow-don-proxy) at `https://wow-don-proxy.fabiosm46.workers.dev`. The backend calls the proxy, which answers CurseForge's `/v1/...` paths without a key, in development too: no `.env`, no `CURSEFORGE_API_KEY`, no `x-api-key` header in the app (#247). The proxy accepts only the ten read-only calls WoW-don makes, forces or checks `gameId=1`, rejects browsers and clients that are not `wow-don/<version>`, rate-limits per client and stores nothing. `WOWDON_CURSEFORGE_PROXY` points a build at another proxy (`https`; loopback `http` only in debug). Zips still come straight from CurseForge's CDN. Limit, stated in the proxy's `SECURITY.md`: no server can prove a request comes from WoW-don, so anyone can use the proxy for what WoW-don does, but never read the key | A key shipped in a desktop app can be extracted; compiling it in was rejected by the user. The proxy keeps the key unreadable and lets it be rotated without a release | Confirmed |

The menu has only "Show WoW-don" (shows, un-minimises and focuses the main window) and "Quit" (always quits, and the plugin of D28 saves the window state); a left click acts like "Show WoW-don" where the platform reports it (Windows, macOS), on Linux AppIndicator opens the menu. | D36 | Start with the system with the official `tauri-plugin-autostart` plugin (2.x), used only by the backend: no `autostart:*` permission for the frontend, which goes through the `get_autostart` and `set_autostart` commands. The operating system entry (on Linux `~/.config/autostart/WoW-don.desktop`, on Windows the `WoW-don` value in `Software\Microsoft\Windows\CurrentVersion\Run`, on macOS the LaunchAgent `~/Library/LaunchAgents/WoW-don.plist`) launches the app with the `--autostart` argument. The operating system is the single source of truth: the state is not copied into `settings.json`, it is reread after every write, and on Windows an entry disabled from the Task Manager counts as off. The main window is declared invisible in `tauri.conf.json` and is shown in `setup`; it stays hidden only if the app started with `--autostart`, `closeToTray` is on and the tray icon is visible at that moment (the same check as D35). The check is made only once, without retrying: if the shell does not show the icon yet the window opens, because an extra window is closed with the X while a hidden one without an icon is unreachable. Limits of the plugin, not configurable: on Windows with the app started as administrator the entry goes into `HKEY_LOCAL_MACHINE` (for all users) instead of `HKEY_CURRENT_USER`, and the executable path is not quoted; in development (`tauri dev`) the entry points to the debug binary | Addons ready at power-on without opening the app by hand; official plugin like D21 and D28. Explicitly approved for issue #159 | Confirmed |
